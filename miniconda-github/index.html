Server / Miniconda

サーバー上にPython仮想環境を作る。

Minicondaを使って、研究・解析・開発用のPython環境をプロジェクトごとに分けて構築します。

手順を見る
ssh server
$ wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh
$ bash Miniconda3-latest-Linux-x86_64.sh
$ conda create -n research python=3.11
$ conda activate research
$ python --version

Setup

Miniconda環境の構築

Linuxサーバーを想定した基本手順です。共有サーバーでは、管理者権限を使わず自分のホームディレクトリに入れる構成が扱いやすいです。

1. サーバーにログイン

手元のPCからSSHで接続します。

ssh ユーザー名@サーバー名

2. インストーラーを取得

Linux用Minicondaをダウンロードします。

wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh

3. インストール

対話に従ってインストール先を選びます。通常は ~/miniconda3 で十分です。

bash Miniconda3-latest-Linux-x86_64.sh
source ~/.bashrc
conda --version

4. 仮想環境を作成

プロジェクトごとに名前を分けると、依存関係の衝突を避けやすくなります。

conda create -n myenv python=3.11
conda activate myenv
python --version

5. 必要なパッケージを追加

Condaで入るものはConda、Python専用ライブラリはpip、と役割を分けます。

conda install numpy pandas scikit-learn
pip install fastapi uvicorn

6. 環境を切り替える

作業を始める時に有効化し、終わったら無効化します。

conda activate myenv
conda deactivate

Troubleshooting

よくあるつまずき

conda が見つからない

source ~/.bashrc を実行します。反映されない場合は ~/miniconda3/bin/conda init bash のあと、再ログインします。

容量が足りない

使っていない環境を conda env remove -n 環境名 で削除し、conda clean -a でキャッシュを整理します。

pipとcondaの依存関係が衝突する

先にCondaで主要パッケージを入れ、最後にpipを使います。依存関係が崩れたら新しい環境を作り直すほうが早い場合があります。
