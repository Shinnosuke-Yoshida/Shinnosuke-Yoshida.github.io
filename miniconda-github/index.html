Setup

Miniconda環境の構築

以下はLinuxサーバーを想定した基本手順です。共有サーバーでは、管理者権限を使わず自分のホームディレクトリに入れる構成が扱いやすいです。

1. サーバーにログイン

手元のPCからSSHで接続します。

ssh ユーザー名@サーバー名

2. インストーラーを取得

公式配布元からLinux用Minicondaをダウンロードします。

wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh

3. インストール

対話に従ってインストール先を選びます。通常は ~/miniconda3 で十分です。

bash Miniconda3-latest-Linux-x86_64.sh
source ~/.bashrc
conda --version

4. 仮想環境を作成

プロジェクトごとに名前を分けると、依存関係の衝突を避けやすくなります。

conda create -n myenv python=3.11
conda activate myenv
python --version

5. 必要なパッケージを追加

Condaで入るものはConda、Python専用ライブラリはpip、と役割を分けます。

conda install numpy pandas scikit-learn
pip install fastapi uvicorn

GitHub

環境をリポジトリで管理する

コードだけでなく、環境の作り方もGitHubに残します。README、環境ファイル、起動コマンドがそろっていると、別サーバーへの移行がかなり楽になります。

project/
├─ README.md
├─ environment.yml
├─ src/
└─ .gitignore

環境ファイルを書き出す

conda env export --from-history > environment.yml

--from-history を付けると、自分で指定した主要パッケージ中心の読みやすいファイルになります。

別サーバーで復元する

git clone https://github.com/ユーザー名/リポジトリ名.git
cd リポジトリ名
conda env create -f environment.yml
conda activate myenv

GitHubへ反映する

git init
git add README.md environment.yml src/
git commit -m "Add reproducible conda environment"
git branch -M main
git remote add origin https://github.com/ユーザー名/リポジトリ名.git
git push -u origin main

Troubleshooting

よくあるつまずき

conda が見つからない

source ~/.bashrc を実行します。反映されない場合は ~/miniconda3/bin/conda init bash のあと、再ログインします。

容量が足りない

使っていない環境を conda env remove -n 環境名 で削除し、conda clean -a でキャッシュを整理します。

GitHubに大きなファイルを上げてしまう

データセット、モデル、ログは .gitignore に追加します。必要ならGit LFSや外部ストレージを検討します。

pipとcondaの依存関係が衝突する

先にCondaで主要パッケージを入れ、最後にpipを使います。再現性が崩れたら新しい環境を作り直すほうが早い場合があります。
